Phase 0 — Khung sườn dự án
- Tạo solution + 4 project theo đúng dependency: Domain (không ref gì) → Application (ref Domain) → Infrastructure (ref Domain + Application) → WebApi (ref Application + Infrastructure).
- Cài NuGet cơ bản: MediatR, FluentValidation, AutoMapper, EF Core, StackExchange.Redis, Hangfire, SignalR, ASP.NET Core Identity, JWT Bearer.
Phase 1 — Domain layer (viết trước tiên, không phụ thuộc gì)
- SeedWork/ (Entity, AggregateRoot, ValueObject, IDomainEvent, DomainException) — viết trước vì mọi entity khác kế thừa từ đây.
- Entity + Enum của Users (User, Address, UserRole) và Catalog (Category, Product, Banner) — đơn giản, làm nóng tay.
- Entity phức tạp hơn: FlashSale/FlashSaleItem, Reservation, Order/OrderItem, Payment — kèm domain event, exception, repository interface tương ứng.
- Domain không có test tích hợp DB nên có thể viết Unit Test ngay ở bước này (test business rule như "không cho trừ kho quá SaleStock").
Phase 2 — Hạ tầng dữ liệu (để có DB chạy được sớm)
- ApplicationDbContext + toàn bộ Configurations/ (EF mapping) → chạy dotnet ef migrations add InitialCreate → có DB thật để test dần các phase sau.
- Seed data cơ bản (1 Admin, vài Category/Product mẫu).
- Repository triển khai cho Users/Catalog trước (đơn giản), Reservation/Order/FlashSale sau.
Phase 3 — Auth & Identity (làm sớm vì mọi API khác đều cần)
- Services/Auth/AuthService.cs + JWT (JwtTokenGenerator, CurrentUserService) + tích hợp ASP.NET Core Identity.
- AuthController — Register/Login/Refresh/Revoke.
Test bằng Postman/Swagger để có token dùng cho các bước sau (mọi endpoint khác cần [Authorize]).
Phase 4 — Module CRUD đơn giản (Service/Repository) — làm để "chạy được hết pipeline" trước khi đụng phần khó
- Services/Admin/ (CategoryService, ProductAdminService, BannerService) + Controller tương ứng.
- Services/UserProfile/ (UserProfileService, AddressService) + Controller.
- Mục đích: xác nhận toàn bộ pipeline DI → Service → Repository → DbContext → SQL Server chạy đúng, xử lý exception middleware ổn định — trước khi đưa Redis/RabbitMQ vào cho phức tạp hơn.
Phase 5 — Catalog Query (CQRS Query-only, thêm Redis)
- IProductCatalogCache + RedisProductCatalogCache.
- CQRS/CatalogQuery/Queries/ (GetProducts, GetProductById, GetActiveFlashSales) — đọc cache, fallback DB.
- Gắn ProductCatalogCacheWarmer vào cuối ProductAdminService để đồng bộ cache khi Admin sửa sản phẩm.
- Đây là bước làm quen với MediatR + Redis trước khi vào phần khó nhất.
Phase 6 — Flash Sale Engine + Reservation (phần khó nhất, nên làm khi đã "ấm tay")
- Domain rule đã có sẵn từ Phase 1, giờ nối dây:
- IFlashSaleStockCache + RedisFlashSaleStockCache (Lua script DECR atomic) — viết và test riêng bằng unit test/script trước khi gắn vào Command.
- CQRS/FlashSaleOrders/Commands/PlaceFlashSaleOrder — Command trọng tâm nhất dự án, viết cẩn thận từng bước: DECR Redis → tạo Reservation → tạo Order Pending → publish RabbitMQ.
- ExpireReservations, ActivateFlashSale, EndFlashSale, SyncFlashSaleStockToDb — các Command phụ trợ.
- BackgroundJobs/ (Hangfire) gọi các Command trên theo lịch.
- Test tải (k6/JMeter bắn nhiều request đồng thời) ngay ở bước này để chứng minh chống oversell — đây là phần "ăn điểm" nhất khi làm CV.
Phase 7 — Payment (CQRS Command còn lại)
- IPaymentGateway + VNPay/MoMo sandbox.
- InitiatePayment, ConfirmPaymentCallback (nhớ idempotency check TransactionCode).
- Event handler confirm Order + gửi Email/Notification.
Phase 8 — Realtime, Notification, Cart, Dashboard (hoàn thiện, ít rủi ro kỹ thuật)
- SignalR Hub + INotificationHub.
- Email templates + SmtpEmailService.
- Cart module (Service/Repository).
Admin Dashboard (query thống kê).
Phase 9 — Bọc ngoài
Middleware xử lý exception (ProblemDetails), Rate Limiter cho FlashSaleOrdersController.
Logging (Serilog), Swagger, health check.
Viết README nêu rõ 3 module CQRS + lý do, kèm kết quả test tải.
